# 狼人杀

## 规则（标准版 + 可简化版）

### 流派说明（必须先定这个，否则规则说不清）

| 流派 | 典型人数 | 特点 | 与本项目的关系 |
| --- | --- | --- | --- |
| **中国线上狼人杀（网易/天天/线下局）** | 9 / 10 / 12 | 有**警长竞选**、**屠边/屠城**、遗言、自爆；角色为「预女猎白」「预女猎守白狼王」等**板子** | ← **建议采用这个流派的骨架**，玩家最熟、观赏性最好 |
| 美式 Werewolf / Mafia | 8~12 | 无警长、白天直接讨论+放逐；常配 Doctor / Detective | 规则最简，适合先跑通 |
| 日式 人狼（AIWolf 平台） | 5 / 9 / 16 | 有**占い師/霊媒師/狩人/狂人**，狼队有**whisper（密语）**通道，协议化 | 见下节 AIWolf，**信息隔离的工程做法最值得抄** |
| One Night Ultimate Werewolf | 3~10 | 只有一夜，靠换牌/查牌，节奏极快 | 不适合多轮养成型观战 |

### 12 人标准局（推荐作为「完整版」参照）

**预女猎白**（4 狼 / 4 民 / 预言家·女巫·猎人·白痴）：

- 狼人 ×4（夜里共同刀人，可自刀、可空刀）
- 村民 ×4（无技能）
- 预言家 ×1（每晚查验一人是「好人/狼人」，结果**只有自己知道**）
- 女巫 ×1（解药 1 瓶、毒药 1 瓶，**每晚最多用一瓶**，全局各一瓶）
- 猎人 ×1（被狼刀或被投票放逐时可开枪带走一人；**被女巫毒杀不能开枪**）
- 白痴 ×1（被投票放逐时翻牌免死，之后**失去投票权但保留发言权**）

**胜负**：

- 好人胜：所有狼人出局。
- 狼人胜：**屠边**——所有平民出局，或所有神职出局（大多数线上平台用屠边）；
  **屠城**——狼人存活数 ≥ 好人存活数（美式/简化版常用）。

> **这点有不同流派**：屠边 vs 屠城直接决定狼队的刀法逻辑，也决定 AI 的「该刀谁」是否可学。
> **建议**：MVP 用**屠城**（判定最简单、不依赖角色分类统计）；完整版可切换到**屠边**，
> 并在提示词的「获胜条件」段里**写清当前用的是哪种**（这条必须进提示词，否则狼队会乱刀）。

**警长（可选）**：第一天竞选，1.5 票权重，死亡时可移交警徽或撕毁，负责定发言顺序与归票。

**平票**：多数平台进入 **PK 发言 → 重投**；简化版可「平票无人出局」。

### 人数与角色配置（最小可用集合）

| 人数 | 狼 | 神职 | 民 | 说明 |
| --- | --- | --- | --- | --- |
| **6** | 2 | 预言家 | 3 | **最小可用集合**。信息量够、4 天内必出结果 |
| 7 | 2 | 预言家 + 女巫 | 3 | 推荐 MVP（女巫提供一次「夜间信息校验」的钩子） |
| 8 | 2 | 预 + 女 + 守卫 | 3 | 守卫引入「同守同救=死」这类边界，先别急 |
| 9 | 3 | 预 + 女 + 猎人 | 3 | 线上最常见的 9 人局，可作为第二档 |
| 12 | 4 | 预 + 女 + 猎 + 白痴 | 4 | 完整版 |

**最小必需角色**：狼人、预言家、平民。**女巫是第二个该加的**（她能把「夜里的信息」和
「白天的发言」连起来，是让 AI 有东西可推理的关键）。猎人/守卫/白痴都属于「爽点与复杂度」，
不是必需。

### 流程 / 回合结构

```
第 N 夜：狼人共同选择击杀目标 → 预言家查验 → 女巫（救/毒/不用）→ 守卫（守护）
   ↓
第 N 天：天亮公布死讯（只公布谁死了，不公布身份；无人死=平安夜）
   ↓（可选）警长竞选：上警 → 竞选发言 → 全体投票 → 警长产生
   ↓
白天自由发言（按顺序或警长定序，每人 1 轮，可加一轮补充）
   ↓
放逐投票（每人 1 票，可弃票；平票 → PK 或无人出局）
   ↓
出局者遗言（可选）→ 猎人开枪（可选）→ 警徽移交（可选）
   ↓
检查胜负 → 下一夜
```

几个**容易写错、必须在提示词里显式说明**的时序点（这些是 AI 的高频幻觉源，见「已知的坑」）：

1. **昨夜的刀口在今天任何发言之前就已确定**，不能用「他今天上警/跳身份」解释昨夜为什么被刀。
2. **普通出局不公开身份**，玩家自报身份只是**声明**，不是事实。
3. **「平安夜」的三种成因**：女巫解药、守卫守住、狼人空刀（有守卫局）/两种（无守卫局）。
4. **猎人被毒不能开枪**；**女巫解药不能救自己**（首夜是否可自救是板子参数）。
5. **守卫同守同救 = 死**（这条最容易漏，漏了就是规则 bug）。

### 可简化的地方（AI 代理版）

**必须保留（砍了就不成立）**：

| 环节 | 为什么不能砍 |
| --- | --- |
| 夜刀（狼人集体选择击杀） | 它是「信息不对称」的发动机，也是狼队唯一的主动技能 |
| 预言家查验（结果私密） | 好人阵营唯一的「硬信息」来源；没有它，好人只能靠感觉，AI 会退化成复读机 |
| 白天公开发言 | 游戏本体。Werewolf Arena 的模拟显示：**不允许交流时好人胜率只有 1.2%** |
| 放逐投票（公开票型） | 票型是第二重要的信息源（谁跟谁同票） |
| 身份不公开 + 死后身份不明 | 一旦公开，推理空间立刻塌掉 |
| 胜负判定（每轮结束检查） | 否则局会无限循环 |

**可以砍（砍了反而更好玩/更快）**：

| 环节 | 建议 | 理由 |
| --- | --- | --- |
| **警长竞选 / 警徽移交** | **第一版砍掉** | 它是「额外的投票轮 + 额外的发言轮」，成本翻倍，但趣味是给老手的；砍掉后一局从 ~6 分钟降到 ~3 分钟 |
| **白痴** | 砍 | 只在特定板子里有意义，且「翻牌后失去投票权」是额外状态 |
| **守卫** | 第一版砍，第二版加 | 引入「同守同救」「不能连守」两个边界，容易写错 |
| **平票 PK 重投** | 简化成「平票 → 本轮无人出局」 | 少一轮全体发言+投票 |
| **遗言** | 简化成「出局者一句公开遗言（≤60 字）」 | 保留信息传递的戏剧性，不占一整轮 |
| **猎人开枪** | 保留（第二版） | 单次动作、极强爽点，成本只要一次调用 |
| **自爆 / 白狼王** | 砍 | 规则分支太多，收益低 |
| **语音、表情、上警手势** | 砍 | 纯文本 |

> **一句话取舍**：留下「夜刀 / 验人 / 发言 / 投票 / 不公开身份」这五件事，
> 狼人杀就还是狼人杀；警长、守卫、白痴是「板子深度」，不是「游戏本体」。

## 提示词设计要点

> 这一节按「能直接抄」的粒度写。下面所有 prompt 片段都是中文、可直接粘贴进 `agent.js` 风格的
> 系统提示词里。

### 1. 信息隔离：怎么表达「你知道什么 / 你不知道什么」

**关键点：隔离不能靠「请不要作弊」，要靠「上下文里根本没有那个字段」。**
狼人杀的 prompt 里**永远不要出现全局身份表**，只出现「这一座位视角的世界」。

推荐用**三段式私有信息块**，把「事实 / 声明 / 未知」硬分开：

```text
【你可以确定的信息】（这些是事实，主持人确认过）
- 你是 3 号，身份：狼人。你的队友：7 号。
- 第 1 夜：你们刀了 5 号。天亮公布：5 号出局。

【你只是听说的】（这些是玩家的声明，不是事实）
- 2 号声称自己是预言家，报 6 号「查杀」。
- 8 号说「2 号像悍跳」。（8 号的说法，未经确认）

【你不知道的】
- 其他每个座位的真实身份。
- 女巫有没有用药、救了谁、毒了谁；守卫守了谁。
- 昨晚狼队的目标是不是被守住或救活了。
```

再配一条**反作弊约束**（这是 wolfcha 那套的简化版，实测有效）：

```text
【引用纪律】
- 你的每一条判断，只能引用上面【你可以确定的信息】和【你只是听说的】里出现过的内容。
- 没出现过的细节一律不存在：不要引用别人没说过的发言，不要描述表情、眼神、语气、
  摸牌动作、声音——这是文字游戏，你看不到这些。
- 玩家原话是「声明」，不是「事实」。要写「2 号声称自己是预言家」，
  不能写「2 号是预言家」。
- 如果你要判断【你不知道的】区间里的事，只能写「我怀疑 / 我认为」，
  不能写「我知道 / 事实上 / 很明显」。
```

**防「假装知道」的三个工程手段**（比提示词可靠）：

1. **公开角色配置只发数量，不发座位**。这是 wolfcha 的一个巧办法：

   ```text
   【本局公开角色配置】狼人×2、预言家×1、女巫×1、村民×3
   说明：这只表示开局每个角色有几个，不对应任何座位，
        也不表示这些角色现在是否还活着。
   ```

   好处：AI 不会以为「7 号是狼」是被系统告知的，同时它又能算「还剩几只狼」。

2. **prompt 快照测试**（本项目扑克已经这么做，「这条有测试守着」）：对 7 个座位各生成一次
   prompt，断言「3 号（狼）的 prompt 里不含 2 号的真实身份字符串」，「平民的 prompt 里不含
   『查验』『解药』这类只属于神职的词」。任何新增字段都必须过这个测试。

3. **后置过滤器**（拦截「说漏嘴」）：`say` 字段写完后跑一遍规则——
   - 出现「我们狼队 / 我的队友」→ 重写；
   - 出现本局真实的刀口人 + 「刀」→ 重写；
   - 出现「我验了 X 号」但该座位不是预言家、或 X 不在其假查验表里 → 重写。
   （扑克的「漏牌检测」`_cleanSayForView` 是同一个位置、同一个思路。）

### 2. 结构化输出：发言 / 投票 / 技能各一套 schema

**最小改动版**（与现有扑克的 `{thinking, say, action, amount}` 对齐，改两个字段名即可）：

```json
{"thinking":"私密推理，两句中文，80 字以内",
 "say":"说出口的话。一句，40 字以内；无话可说时留空",
 "action":"speak|vote|skill|pass",
 "target":4,
 "reason":"投票/技能的一句公开理由，25 字以内，不含私有信息"}
```

**推荐版（多气泡 `say`，画面更像真人）**——wolfcha 就用 `["第一段","第二段"]` 的形式，
前端可以一条一条打出来，节奏感远好于一次糊一大段：

```json
{"thinking":"2 号跳预言家报了 6 号查杀，但 2 号的发言顺序不对；我倾向不信。",
 "say":["先说结论：我不太信 2 号的预言家。",
        "理由有两个：一是他报验的时机太晚，二是他跟 4 号的票型对不上。",
        "我这一票先给 2 号。"],
 "read":{"2":"悍跳嫌疑","6":"被冤枉可能","4":"跟票"},
 "vote_intent":2}
```

**投票专用 schema**（把「改票」变成一等公民，这是修「投票与发言不一致」的关键）：

```json
{"thinking":"私下分析，不超过 200 字",
 "vote":2,
 "reason":"可以公开说出口的一句话理由",
 "changed_from":4}
```

**技能专用 schema**：

```json
{"thinking":"…", "action":"kill|save|poison|check|guard|shoot", "target":5}
```

各字段的硬规矩：

| 字段 | 规矩 | 为什么 |
| --- | --- | --- |
| `thinking` | **中文、口语、≤80 字（发言）/≤200 字（投票）**；禁止英文推理、禁止 JSON 残渣、禁止复述提示词 | 荷官模式要把它显示在桌上；英文/markdown 会让气泡变成垃圾（扑克的 `cleanThinking` 已经在治这个） |
| `say` | 要有实际信息量；不许「我是好人，过」 | 见「套话」那一节 |
| `reason` | 必须是**能当众说出口**的版本 | 防止把私有信息（查验结果、狼队友）写进公开理由 |
| `target` | 必须落在**本阶段合法候选集**里，代码校验；非法 → 重试一次 → 仍非法则**弃票/放弃** | 「随机挑一个合法目标」会毁掉策略一致性（灰雾村文档明确把这条列为待改进项） |
| `changed_from` | 只有出现「新的身份声明 / 新查验 / 警长归票 / 主持人公告」才允许非 null | 保证「改票要有理由」 |

**解析层要做的**（复用扑克已有的能力）：剥代码块 → 容错解析 → 运行期 schema 校验（不要只信
TypeScript 泛型）→ 失败重试 1 次 → 确定性降级。

### 3. 多轮发言与记忆：三层结构 + 事件账本

狼人杀一局下来，7 人 × 4 天，原始 transcript 轻易破 5k token，加上票型、夜间公告与遗言会更长。
**不要把原始 transcript 当记忆**。推荐三层（扑克已经有第 3 层的完整实现，第 2 层只有「最近几手」的滑窗）：

```
第 1 层：结构化事件账本（唯一的真相源，全量保留，但不全文塞进 prompt）
第 2 层：每日摘要（一天一条，6~12 个 bullet，客观记录）
第 3 层：私有笔记（每个座位一条怀疑度 + 一句理由，自己维护）
```

**第 1 层：事件账本**。每个事件有 id、类型、可见性：

```json
{"id":"D2-S3","type":"speech","seat":5,"day":2,"round":1,
 "text":"2 号报 6 号查杀，我觉得 2 号是真的。","visibility":"public"}
```

可见性三档：`public`（所有人）/ `faction`（仅狼队）/ `secret`（仅本人）。
**只有 `public` 事件能进别人的 transcript**——这是信息隔离在数据层的落点。

**第 2 层：日摘要**。抄 wolfcha「客观记录员」的约束，写得非常好，直接可用：

```text
你是狼人杀客观记录员。把当天白天记录压缩为要点列表，作为后续回合的长期记忆。

核心原则
- 客观记录每位玩家说了什么、做了什么，不加主观判断。
- 玩家自称、查验声明和身份判断必须写成「某号声称/认为」，
  不能改写成主持人已确认的事实。
- 普通出局不公开身份，不能据此断言当前剩余某角色的确切数量。
- 死因只记录主持人明确公开的内容；未公开时写「死因未公开」，
  不要自行推断狼刀、毒杀或守救。
- 保留事件实际发生阶段：白天投票、遗言、猎人开枪不能记到昨夜。

必须包含
1. 昨夜公开结果：平安夜 / 谁出局 / 主持人公开的死因或「死因未公开」
2. 身份声明：谁声称什么身份、报了什么查验
3. 每位发言玩家的核心观点（每人 1 句话）
4. 站边关系：谁支持谁、谁质疑谁
5. 投票结果：谁被放逐、得票分布
输出：{"bullets":["…","…"]}（通常 6~12 条，确保每位发言玩家都被记录）
```

**第 3 层：私有笔记（「记事本」机制）**。这是让 AI 有「人味」和跨轮一致性的关键，
扑克的「读人笔记 / 每 3 手更新一次」可以直接搬到狼人杀（每 1 天更新一次）：

```text
【你的读人笔记】（只有你能看到，可以保留/修正/推翻）
- 2 号：跳预言家，报 6 查杀。可信度 40%——报验时机太晚。
- 6 号：被 2 号查杀后反应激烈，但没有硬证据。可信度 50%。
- 4 号：跟 2 号的票，但发言像好人。可信度 60%。
输出 JSON：{"notes":{"2":"…","4":"…","6":"…"}}
```

**上下文预算**（7 人局，单次调用）：

| 块 | tokens |
| --- | --- |
| 系统提示词（规则 + 角色 + 性格） | 600~900 |
| 私有信息块 | 200~400 |
| 历史摘要（逐日 bullet） | 300~600 |
| 当日 transcript（逐字，保留近 2 轮） | 800~1500 |
| 事件账本里的关键事实（票型 / 查验 / 死亡） | 200~400 |
| 读人笔记 | 150~300 |
| **合计** | **约 2.5k~4k** |

> 反例警示：某中文实现把公共日志压到「最近 25 条」，结果**早期的站边、假报验和承诺被截断**，
> 后面就开始自相矛盾。结论：**逐字文本可以滑窗，事件账本和笔记不能滑窗。**

### 4. 欺骗与推理：让「撒谎」是可控策略，而不是胡编

**核心区分（这条要写进所有狼人提示词）**：

```text
【撒谎的边界】
- 允许：隐藏身份、谎报身份、编造查验结果、误导他人、假装好人。
- 不允许：引用不存在的发言/投票/死亡；把没发生的夜晚结果当事实；
  说出只有狼队才知道的信息（队友是谁、今晚刀了谁）。
换句话说：你可以骗人，但不能编造这个世界发生过什么。
```

> 出处：灰雾村文档的一句话——「狼人假称预言家是玩法；AI 把不存在的上一轮发言当证据是质量缺陷。
> 不能因为狼人杀允许说谎，就把所有幻觉解释为合理行为。」这句话建议直接贴进项目注释。

**给狼人发「伪装身份卡」**（把自由发挥收敛成可执行的剧本）：

```text
【你的伪装】
当前伪装：预言家（悍跳）。
你的假查验表（只能报这几条，多一条都不行）：
- 第 1 夜验 4 号 → 好人
- 第 2 夜验 6 号 → 狼人
后续每晚你还要「补一条」新查验，保持每晚一条的节奏。
禁止：报出表外的查验；说「我们狼队」；提到真实刀口。
```

「假查验表」这个做法值得抄：模型有很强的「补全」冲动，给它一张固定的表，
它就不会编出第 3 条、第 4 条自相矛盾的查验。

**狼人策略菜单**（不给菜单，模型只会「装好人」一种玩法）：

```text
【狼队可选的打法】（自己挑一个，选定后全程保持一致）
1. 深水：装成普通好人，只给怀疑对象，不跳身份。
2. 悍跳：抢跳预言家，报一张假查验表，把真预言家做成「悍跳狼」。
3. 倒钩：站真预言家这边，骗取信任，后期带节奏。
4. 自刀：夜里刀自己，白天博同情（只在需要做高身份时用）。
```

**发言一致性检查（防「投票≠发言」）**——抄 wolfcha 的投票约束，写成硬规则：

```text
【一致性】
- 如果你今天的公开发言里说过要投谁，默认就投那个人。
- 只有在你说完那句话之后，出现了新的身份声明、新的查验结果、警长归票
  或主持人公告，才允许改投，并且在 reason 里写明是哪一条。
- 如果发言里没说过投谁，按 analysis 的结论决定，不要编造「我早就说了」。
```

**防自曝的 checklist（给狼的自我检查清单）**：

```text
发言发出去之前，自查：
1. 有没有出现我队友的座位号？
2. 有没有提到今晚/昨晚真实刀了谁？
3. 有没有说「我是狼」「我们狼人」这类话？
4. 我说的查验条数，是否正好等于我声称验过的夜数？
5. 我有没有引用自己其实没说过的话？
任何一条中了，重写这段发言。
```

**给好人的推理脚手架**（防止「我觉得他像狼」这种零信息发言）：

```text
【今天该看什么】
- 谁跳了身份、有没有人对跳（一真一假？还是双狼演戏？）
- 谁的票型和发言对不上（说投 A 却投了 B）
- 谁在「跟票」而不给理由
- 昨晚的刀口和今天的发言有没有矛盾（谁在替死人说话？）
【发言必须包含】
① 我今天最怀疑谁、为什么（引用具体某句话/某个票型）
② 我今天最相信谁、为什么
③ 我这一票打算给谁（或我在哪两个人之间犹豫，各自的依据）
```

### 5. 发言长度与节奏

参考三个来源校准：扑克是「一句话 20 字以内」，狼人杀**必须更长**（要有论点）；
Werewolf Arena 的实测结论是「**啰嗦=可疑**」（GPT-4 长篇大论反而被当成狼）；
wolfcha 的默认要求是「4~6 句」。

| 场景 | 建议长度 | 备注 |
| --- | --- | --- |
| 白天首轮发言 | **120~220 字**（3~5 句） | 必须包含「怀疑谁 / 信谁 / 投谁」三件套 |
| 白天后续轮 / 补充发言 | **60~150 字**（2~4 句） | 只讲新增信息，禁止复述上一轮 |
| 被点名后的回应 | **40~100 字**（1~3 句） | 先回应指控，再反打 |
| 悍跳预言家（狼） | **200~300 字** | 要报完整查验表 + 警徽流，最长的一档 |
| 遗言 | **60~150 字** | 只留结论与嘱托 |
| 投票 `reason` | **≤25 字**，一句话 | 公开可见，不能含私有信息 |
| `thinking`（私密） | **≤80 字**（发言时）/ **≤200 字**（投票时） | 荷官模式会显示，要像人话 |
| **气泡切分** | 每次发言 2~4 条，每条 15~40 字 | 一条一句，前端逐条打字机，节奏最好 |

**节奏控制建议**（对「看 AI 玩」体验影响极大）：

- 夜里三个角色**并行**请求（互不依赖），白天发言**串行**（后者要听前者）。
- 每人发言之间的停顿可配（扑克已有「行动前停顿」），默认 0.6~1.2s，让观众看得清。
- 投票可以**并行**发起、按座位顺序逐个揭晓（保留「谁先投」的戏剧性）。
- 日摘要**异步**做，不要卡在下一夜开始前。

### 6. 已知的坑（别人踩过的，按严重程度排）

| # | 坑 | 典型表现 | 处方 |
| --- | --- | --- | --- |
| 1 | **编造前情** | 「他上轮发言很沉稳，所以我验他」「他眼神躲闪」——可首夜根本没有发言/没有表情 | 三段式信息块 + 引用纪律 + 「首夜验人允许随机或按座位偏好，不必编心路历程」（灰雾村原话） |
| 2 | **时间线倒置** | 用「他今天上警」解释「昨夜为什么被刀」 | 提示词写死阶段顺序，并加一句「昨夜刀口在今天任何发言之前已锁定」 |
| 3 | **把声明当事实** | 「2 号是预言家」写成既成事实，后面所有推理都建在沙上 | 强制「声称/认为」措辞；摘要 prompt 里也强制 |
| 4 | **投票与发言不一致** | 发言说投 4 号，投票投了 7 号，且无理由 | `changed_from` 字段 + 一致性规则 + 违规重写 |
| 5 | **说漏嘴 / 自曝** | 狼人说出队友、「我们狼队」、真实刀口 | 后置过滤器（同扑克的漏牌检测），命中即重写 |
| 6 | **全员套话** | 每个人都「我是好人，我怀疑 3 号，因为他的发言很飘」 | 发言必须含「具体引用 + 新信息」；禁止无信息声明；persona 给不同的「发言长短/推理方式/常见误判」 |
| 7 | **复读机** | 连续两轮说同一段话，或所有人都在「归票」 | 首轮之后禁止复述；提示「只讲新增信息」；日摘要里标注「已说过的观点」 |
| 8 | **随机兜底毁一致性** | 解析失败就随机挑一个目标 → 上一秒还说信他，下一秒投他 | 降级必须是**确定性且保守的**：弃票 / 不用药 / 放弃开枪，而不是随机 |
| 9 | **上下文截断丢承诺** | 早期「我保 5 号」被滑窗挤掉，后期反过来打 5 号 | 事件账本 + 私有笔记全量保留；只滑窗逐字文本 |
| 10 | **位置偏置** | 总投列表里的第一个人 / 最后一个 | 每次把候选顺序**随机打乱**（Werewolf Arena 的做法） |
| 11 | **长篇=可疑 / 全短=没信息** | 两种极端都出现 | 按角色/场景给长度区间（见上表），悍跳最长、回应最短 |
| 12 | **「预言家」无脑被信** | 谁跳预言家谁赢，狼队没得玩 | 提示「只有一名玩家跳预言家且无人对跳时才是大概率真；有人对跳通常一真一假」；鼓励对跳（狼的悍跳是必修课） |
| 13 | **模型跳出角色** | 说「作为一个 AI」「根据规则第 X 条」 | 明确「你在牌桌上，不是裁判，不是解说」；禁职业类比/场外经历（wolfcha 有这条） |
| 14 | **成本/延迟爆炸** | 12 人局一晚上百次调用 | 7 人局起步；夜间并行；摘要异步；投票并行 |

## 实现建议（最小可行版本）

### 板子与规模

- **人数**：7 人（2 狼 / 预言家 / 女巫 / 3 民）——最小但信息足够。
  如果还要更省，**6 人（2 狼 / 预言家 / 3 民）**也能跑，只是少一个夜间信息校验点。
- **轮次上限**：4 天。到时按存活人数判（狼多则狼胜）。
- **砍掉**：警长、守卫、白痴、PK 重投、自爆。
- **保留**：夜刀、验人、女巫救/毒、公开发言（1 轮）、放逐投票、平票无人出局、
  一句遗言、身份不公开、每轮判胜负。

### 一局的调用量

```
夜：狼队会议 1 次 + 预言家 1 次 + 女巫 1 次 = 3 次
天：发言 6 次（存活人数） + 投票 6 次 + 日摘要 1 次 = 13 次
每天 ≈ 16 次；4 天 ≈ 60~65 次调用
单次 1~4s（串行）→ 一局 3~6 分钟；夜间并行 + 投票并行可压到 2~3 分钟
```

### 代码分工（对应现有目录）

| 模块 | 职责 | 复用扑克的部分 |
| --- | --- | --- |
| `src/games/werewolf/kernel.js` | **纯规则**：状态机（夜/天/投票/结算）、角色技能、胜负判定、票数统计 | 新写（可借 `src/core` 的「纯函数 + 无 UI 依赖」风格） |
| `src/games/werewolf/view.js` | `buildView(state, seat)` → 该座位能看到的全部内容；**唯一的信息出口** | 新写（这是本项目最该写测试的地方） |
| `src/games/werewolf/prompts/` | 角色 prompt 模板（狼 / 预 / 女 / 民）、发言模板、投票模板、日摘要模板 | 新写，但**结构抄 `agent.js` 的 persona + 私有信息 + 输出格式三段式** |
| `src/ai/agent.js`（改造） | LLM 调用、流式、JSON 容错解析、`cleanThinking`、漏牌检测、重试降级 | **几乎全复用**，只加 `mode: 'werewolf'` 的 schema |
| `src/games/werewolf/memory.js` | 事件账本、日摘要、读人笔记 | 复用的「读人笔记」思路（`notes` + `notesEvery`） |
| `src/ui*` | 座位、身份卡、投票面板、夜间遮罩、回顾（上帝视角） | 复用座位/立绘/节奏控制/回顾面板 |

### 「看 AI 玩」vs「自己也加入」

| 模式 | 你看到 | 你要做的事 | 关键实现 |
| --- | --- | --- | --- |
| **上帝/荷官模式** | 所有人的身份 + 所有人的 `thinking` + 夜间行动全流程 | 只控制节奏（下一位 / 自动 / 暂停 / 重开） | 前端拿全量 state；`thinking` 全程可见（和扑克的荷官模式一致） |
| **玩家模式** | 只有你自己的身份 + 公开信息；`thinking` 全部隐藏 | 按阶段行动（夜里的技能、白天的发言与投票） | 前端**只拿自己视角的 view**；结算后再一次性解锁全场 `thinking`（扑克的「回顾面板」） |

> ⚠️ **安全提醒（对浏览器版很重要）**：扑克浏览器版把牌局状态放在前端，玩家模式靠「不渲染」隐藏底牌。
> 狼人杀如果照搬，身份表会出现在页面内存里，随手 F12 就能看穿。要么玩家模式走**服务端权威状态**
> （Worker 里跑 kernel，只下发布尔/枚举级的 view），要么明确接受「单机自己骗自己」并写进文档。
> 建议：**上帝模式可以纯前端；玩家模式必须服务端裁剪 view。**

# 谁是卧底

## 规则（标准版 + 可简化版）

### 标准规则（大陆聚会版，最常见）

- **人数**：4 人以上；**6~8 人体验最好**。
- **身份**：平民 / 卧底 /（可选）白板。
  - 平民：所有人拿**同一个词**。
  - 卧底：拿一个**相近但不同**的词（如 平民「牛奶」/ 卧底「豆浆」）。
  - 白板：**不拿词**（可选，用来加难度；白板要假装自己也有词）。
- **卧底数量**（这点有不同流派，各地约定不一）：
  - 6 人及以下：**1 个卧底**（最常见）；
  - 7 人以上：常见的两种做法是「仍然 1 个卧底（更难）」和「2 个卧底（更快）」。
  - **建议采用**：6 人 1 卧底、8 人 2 卧底，并把它做成房间参数写进规则说明；**白板默认关**。
- **核心机制（和狼人杀最本质的区别）**：**玩家只知道自己拿到的词，不知道自己是不是卧底。**
  卧底要靠「别人说的跟我对不上」自己意识到。这一点是整个提示词设计的支点。
- **流程**：
  ```
  发词（私密） → 第 1 轮描述（轮流，每人一句） → 投票 →
     得票最多者出局（平票 → PK 或重投） → 第 2 轮描述 → 投票 → …
  ```
- **描述规则**：不能直接说出这个词；不能说太具体（会被卧底抄）；通常**一句话、20 字以内**。
- **胜负**（采用 [九游规则页](https://www.9game.cn/sheishiwodi/10914923.html) 的口径，这版最常见）：
  - 平民胜：所有卧底（及白板）出局。
  - 卧底胜：**人数 <6 时，卧底活到只剩 2 人；人数 ≥6 时，卧底活到只剩 3 人。**
  - 白板胜：所有卧底出局且白板存活。
- **平票**：进入 PK（平票者各说一句）→ 在平票者中重投。

> **两个必须做决定的流派点**：
> 1. **出局是否公开阵营**？多数版本在「卧底出局 → 游戏直接结束」的规则下，**等于公开**。
>    若用 2 卧底，建议**出局即公开阵营**（否则好人完全拿不到反馈，AI 会瞎投）。
>    **建议采用：公开阵营。**
> 2. **描述顺序**是否固定？固定顺序会带来「位置优势」（越晚说越能抄）。
>    **建议采用：每轮随机起始座位、方向固定**（公平且可解释）。

### 可简化的地方（AI 代理版）

| 环节 | 建议 | 理由 |
| --- | --- | --- |
| 白板 | **砍** | 白板要演「有词」，对 LLM 是纯额外难度，对观众是额外困惑 |
| PK 重投 | **砍**（平票 → 本轮无人出局） | 少一轮，节奏更快 |
| 淘汰后「遗言/辩解」 | **砍** | 谁是卧底的乐趣在描述，不在遗言 |
| 多轮描述直到人数耗尽 | **保留，但设 4 轮上限** | 6 人 4 轮必出结果，避免僵局 |
| **「不知道自己是卧底」** | **必须保留** | 这是游戏灵魂；一旦告诉 AI「你是卧底」，它会立刻开始表演，游戏就假了 |
| 词对难度 | **必须做平衡** | 词对太近 → 投不出去；太远 → 第一轮就抓出来。建议人工筛 50~100 对 |
| 每轮 1 句描述 | **必须保留** | 一句话是核心限制条件，长了就变成狼人杀 |
| 投票理由 | 可选加（传统没有） | 加一句 20 字理由，观赏性更好，且给 AI 一个「表态」的出口 |

## 提示词设计要点

### 1. 信息隔离：这一节的难点是「连自己是不是卧底都不能告诉它」

狼人杀是「你知道自己的身份，但要藏住」；谁是卧底是「**你不知道自己的身份，要靠推理猜**」。
所以提示词不能写「你是卧底/你是平民」，只能给**词 + 公开历史**，再教它怎么自省。

```text
【你拿到的词】葡萄
（只有这一个词是你的私有信息。本局所有平民拿同一个词，卧底拿一个相近但不同的词。）
（你不知道自己在哪一边。）

【公开信息】
- 存活：1、2、3、4、5、6 号（你在 3 号）
- 第 1 轮描述：
  1 号：「紫色的，一串一串的。」
  2 号：「夏天很常见，冰过更好吃。」
  4 号：「要吐皮，也有无籽的。」
  5 号：「可以做成果汁或者酒。」
  6 号：「小小一颗，很甜。」
【你不知道的】
- 谁是卧底、卧底词是什么、你自己是不是卧底。
```

**自省推理链**（抄 11zhouxuan 那份，实测好用）：

```text
【先判断自己站在哪一边】
- 逐个看别人的描述：和我的词「葡萄」对得上吗？
- 只要有一个人的描述明显和我的词吻合，那我和他应该都是平民。
- 如果场上所有人的描述都跟我的词对不上，那我大概率是卧底——
  这时不要去纠正别人，而要顺着大家的说法描述。
```

**防「假装知道」/ 防作弊**：

```text
【禁止】
- 不能说出、写出、暗示你拿到的词本身（包括同音、拆字、直接翻译）。
- 不能说自己「是平民」或「是卧底」——你不知道，也不许编。
- 不能引用没有出现过的描述。
- 不能评价「这个词」的元信息（例如「这个词有几个字」「这是个名词」）——
  现实里没人会这么说，会直接被当成卧底。
```

**工程隔离**：平民 prompt 里**绝不能出现卧底词**；卧底 prompt 里**绝不能出现平民词**；
两者都不能出现「卧底/平民」这个阵营字段。→ **必须写快照测试**：
「平民 prompt 不含卧底词字符串」「任何 prompt 不含 `faction` 字段」。

### 2. 结构化输出：描述 / 投票两套

**描述**（一句 + 私密思考）：

```json
{"thinking":"2 号说夏天冰过更好吃，跟我对得上，他应该也是平民。我这轮说形状吧。",
 "say":"圆圆的，一颗一颗长在藤上。",
 "self_read":"civilian",
 "avoid":"葡萄"}
```

- `self_read` ∈ `civilian | undercover | unsure`：**这是给观众看的最大乐趣来源**
  （「它居然猜到自己就是卧底」），也是我们做「荷官模式」时最值得展示的字段。
- `avoid` 是可选字段（要求模型自己声明「我这句没碰到的词」），可用于校验。

**投票**：

```json
{"thinking":"6 号的描述和所有人都对不上，他最可疑。",
 "vote":6,
 "reason":"6 号说的「小小一颗很甜」跟我们几个说的都不太一样。"}
```

投票硬规矩：
- 不能投自己（卧底尤其）；
- 不能投已出局的人；
- 不能弃权（简化版可以允许弃权，但要显式标注）；
- `reason` ≤25 字、能让别人听见（不许写「因为我是卧底所以投他」）。

### 3. 记忆：这是一个「短程」游戏，用表格而不是摘要

谁是卧底一般 3~4 轮就结束，**不需要日摘要**，但**极其需要「描述矩阵」**——
因为核心推理就是「横向对比所有人说过的话」。

```text
【描述矩阵】（第 1~3 轮，每格是原话）

座位  第1轮                 第2轮                 第3轮
1号   紫色的，一串一串的。    有籽的比较多。        —
2号   夏天很常见，冰过更好。  可以酿酒。            —
3号（你）圆圆的，长在藤上。   一颗一颗挤在一起。    —
4号   要吐皮，也有无籽的。    晒干了也能吃。        —
5号   可以做成果汁或者酒。     —
6号   小小一颗，很甜。        红色的。              —
```

再加一张「我的判断表」（每轮更新一次，等价于扑克的读人笔记）：

```text
【我的判断】
- 2 号：描述和我高度吻合 → 平民（80%）
- 4 号：吻合 → 平民（75%）
- 6 号：「小小一颗很甜」太泛，谁都能说 → 可疑（40%）
- 5 号：只提用途不提外形 → 可疑（45%）
- 我自己：有 3 个人跟我对得上 → 我应该是平民
输出：{"read":{"2":80,"4":75,"6":40,"5":45},"self":"civilian"}
```

**上下文预算**（6 人局，单次调用）：系统 400 + 词 20 + 矩阵 300~600 + 判断表 80
= **约 1k tokens**，非常轻。这也是为什么谁是卧底适合先做（便宜、快、试错成本低）。

### 4. 欺骗与推理：卧底要「寄生」，平民要「给锚点」

**平民的两难**（必须写进提示词，否则模型会走极端）：

```text
【描述的分寸】
- 说得太具体 → 卧底直接抄你的话，你就白给了。
- 说得太模糊 → 你自己看起来最像卧底。
- 建议：描述一个「真实的、但不唯一」的特征。既让同伴能认出你，
  又不足以让卧底照抄。
- 第一轮尤其要留手；后面几轮可以逐步说得更具体，
  因为那时候「谁在抄」已经能看出来了。
```

**卧底策略菜单**（不给菜单，模型只会「说得很泛」然后被投）：

```text
【卧底（如果你判断自己是）的三种打法】
1. 寄生：挑一个平民的描述，用不同的角度补一个同类特征，跟着大流走。
2. 抢先：第一轮就说得比较具体（冒险），赌别人不敢投你。
3. 制造分歧：抓住两个描述之间的细微差异，把水搅浑（后期用）。
【铁律】不要复读别人的原话；不要说得比所有人都空；不要给自己找理由开脱。
```

**抄描述检测（工程手段，比提示词可靠）**：

- 计算本轮描述与历史描述的**字符 n-gram 重合度**，超过阈值（如 0.6）→ 打回重写；
- 提示词里也要写：「不能与历史发言重复，不能换个说法说同一件事」。

**禁止自曝的检查**（后置过滤器）：

- `say` 里出现自己的词 → 重写（这是最硬的规则，**必须代码拦截**，不能只靠提示）；
- `say` 里出现「我是平民/我是卧底/我的词是」→ 重写；
- 出现「这个词」「这两个字」这类元信息 → 重写。

### 5. 长度与节奏

| 内容 | 建议长度 | 备注 |
| --- | --- | --- |
| **描述 `say`** | **10~20 字，一句话** | 常见约定是「一句话、20 字以内」（有的圈子放宽到 30 字）；这是游戏的核心限制，别放宽 |
| `thinking`（私密） | 40~100 字 | 荷官模式展示用；要有「横向对比」的痕迹才好看 |
| 投票 `reason` | ≤25 字 | 一句 |
| 轮次节奏 | 每轮：全体描述（串行，~6 次调用）→ 投票（并行或串行）→ 公布 → 1 次结算检查 | 一轮 10~15 秒，一局 2~3 分钟 |
| 发言顺序 | 每轮随机起始座位，方向固定 | 避免位置优势；但方向固定让观众跟得上 |

### 6. 已知的坑

| # | 坑 | 表现 | 处方 |
| --- | --- | --- | --- |
| 1 | **说出来自己的词** | 「我的是葡萄」/「紫葡萄」 | 代码级关键词过滤（含近义词表）+ 重写 + 该轮降级为「过」 |
| 2 | **全员模糊** | 所有人都在说「很好吃」「很常见」，游戏零信息 | 提示词给「具体但不唯一」的分寸；评审里加「信息量」指标；必要时加一条「本轮描述必须提到一个具体属性（形状/颜色/用途/口感之一）」 |
| 3 | **卧底复读抄袭** | 卧底直接重复/改写在别人说过的描述 | n-gram 重合度检测打回；提示词明令禁止 |
| 4 | **AI 不知道自己是卧底而崩** | 卧底坚信自己是平民，疯狂纠正别人 → 立刻被抓 | 自省链（「所有人跟你都对不上 → 你大概率是卧底」）+ 允许 `self_read: unsure` |
| 5 | **模型直接报阵营** | 「我是平民，请相信我」 | 禁止条款 + 过滤器 |
| 6 | **投票和描述不一致** | 说 4 号可疑，却投了 6 号 | `reason` 必须与 `thinking` 的结论一致；投票前把本轮自己的描述一起塞进 prompt |
| 7 | **平票死循环** | 两轮都平票，游戏卡住 | 平票 → 无人出局 + 进入下一轮；4 轮上限强制结算 |
| 8 | **词对太难/太易** | 太近：投不出去；太远：第一轮就抓 | 人工词库 + 可加「难度」标签；难词对留给 2 卧底局 |
| 9 | **元信息泄漏** | 「这个词有三个字」 | 禁止条款 + 过滤器 |
| 10 | **玩家角色泄底（人类局）** | 人类玩家看到自己的词和身份表 | 见「共同工程问题」的安全提醒 |

## 实现建议（最小可行版本）

- **人数**：**6 人 = 5 平民 + 1 卧底**（最稳、最容易调平衡）；8 人版做 2 卧底。
- **词库**：**50~100 对**，人工筛，成对存储：`{"civilian":"牛奶","undercover":"豆浆","difficulty":2,"tags":["食物"]}`。
  第一版只需要「食物 / 日用品 / 动物 / 数码」四个类目。
- **轮次**：上限 4 轮；每轮「描述 → 投票 → 公布」。
- **调用量**：6 人 × 4 轮 × (描述 1 + 投票 1) ≈ 48 次；单次 0.5~2s（句子短）→ **一局 1~2 分钟**。
- **代码分工**：

| 模块 | 职责 | 复用 |
| --- | --- | --- |
| `kernel.js` | 发词、描述顺序、计票、平票、胜负（含「剩 3 人」规则） | 新写，逻辑比狼人杀简单一个数量级 |
| `view.js` | 每个座位只拿到「自己的词 + 公开描述矩阵」 | 新写；**与狼人杀共用同一套 view 构建范式** |
| `words.js` | 词对库 + 难度 + 类目 | 新写 |
| `prompts/` | 描述模板、投票模板、自省模板 | 新写，可抄 `sci-m-wang` 与 `11zhouxuan` 的结构 |
| UI | 座位、发言气泡、矩阵表、投票面板、**「它猜自己是卧底」的高亮** | 复用座位/气泡/节奏 |

- **两种模式**：
  - 上帝模式：能看到每人的词、阵营、所有人的 `thinking`（尤其是 `self_read` 的变化，这是最好看的部分）；
  - 玩家模式：只看到自己的词 + 公开矩阵；投票时自己点；结算后解锁全场。

# 两个游戏的共同工程问题

## 1. 架构：确定性的 Kernel + 只说话不算数的 Agent

两个游戏都可以拆成同一套四层，且和现有扑克的 `core/` + `ai/agent.js` + `ui/` 对得上：

```
Kernel（纯函数，无 LLM、无 UI）
   └─ 状态机 + 合法动作集 + 结算 + 胜负
ViewBuilder（唯一的信息出口）
   └─ buildView(state, seat) → 只含该座位有权看到的字段
AgentRunner（LLM 层）
   └─ prompt 组装 → 调用 → 容错解析 → schema 校验 → 后置过滤 → 降级
Presenter（UI）
   └─ 上帝模式：全量 state；玩家模式：只拿自己的 view
```

**铁律**：任何「谁出局了 / 谁是什么身份 / 票够不够」的判断只能由 Kernel 做。
LLM 的输出一律视为**提议**（proposal），非法就拒。这就是
「An Implementation of Werewolf Agent That does not Truly Trust LLMs」的核心主张。

## 2. 信息隔离：一套机制，两个游戏共用

| 手段 | 狼人杀 | 谁是卧底 | 共用？ |
| --- | --- | --- | --- |
| 事件可见性三档（public / faction / secret） | 狼队密语、查验、用药 | 只有「自己的词」是 secret | ✅ 共用 |
| `buildView(state, seat)` 单一出口 | 必需 | 必需 | ✅ 共用 |
| 公开配置只发数量不发座位 | 角色构成表 | 无（不需要） | ✅ 狼人杀 |
| prompt 快照测试 | 断言不含他人身份 | 断言不含对方阵营的词 | ✅ 共用一套测试框架 |
| 后置过滤器（说漏嘴） | 队友/刀口/假验条数 | 自己的词/阵营/元信息 | ✅ 共用，规则不同 |
| 协议层隔离（AIWolf 的 talk/whisper 分通道） | 强烈建议 | 不需要 | 概念共用 |

**「声明 vs 事实」要成为数据模型的一部分**，而不是提示词里的口号：

```js
// 建议：说话是一个事件，不是事实
{ type: 'claim', speaker: 2, about: 6, claim: 'werewolf',
  source: 'player_claim', verified: false }   // ← verified 只有主持人能改
```

## 3. 记忆：三层结构 + 事件账本，两个游戏共用 80%

| 层 | 狼人杀 | 谁是卧底 | 说明 |
| --- | --- | --- | --- |
| 事件账本（全量、带 id、带可见性） | ✅ 必需 | ✅ 必需（描述矩阵就是它的投影） | **共用实现** |
| 摘要（压缩长历史） | ✅ 每天一条 | ❌ 不需要（轮次太少） | 狼人杀专有 |
| 私有笔记（读人/读词） | ✅ 每轮一次 | ✅ 每轮一次（判断表） | **共用实现**，字段不同 |
| 引用校验（引用的发言是否真实存在） | ✅ 强烈建议 | ✅ 建议 | **共用实现**：拿 `say` 里的引号内容去账本里查 |

**引用校验**值得单独写一下（这是最能压住「编造前情」的一招）：

```js
// 从发言里抽出「X 号说过『…』」的引用，去账本里找
const quotes = extractQuotes(speech);       // [{seat, text}]
const ok = quotes.every(q => ledger.hasUtterance(q.seat, q.text));
if (!ok) → 重写一次，仍失败 → 本条发言降级为「不引用历史」的短发言
```

## 4. 结构化输出：一个信封，多套 schema

两个游戏 + 现有扑克，建议统一成同一个信封，只是 `action` 域不同：

```json
{"thinking":"私密，中文",
 "say":["公开，1~4 条"],
 "action":"fold|check|call|raise|speak|vote|skill|describe|pass",
 "target":4,
 "amount":null,
 "reason":"公开一句理由（投票/技能用）",
 "extra":{}}
```

校验与降级的统一策略（**这条比 schema 本身更重要**）：

```
解析失败 → 重试 1 次（加一句「只输出 JSON」）
   ↓ 仍失败
按 action 域做「安全降级」，且必须是确定性的：
  扑克：check/fold（已有）
  狼人杀发言：一句无引用的短发言（不编造）
  狼人杀投票：弃票（不是随机投）
  狼人杀技能：不用药 / 放弃开枪 / 空刀（不是随机）
  卧底描述：一句极模糊的通用描述（并标记 quality=low）
  卧底投票：弃权（并在回放里标注）
```

> 为什么强调「不能随机」：随机兜底会让**同一局内前后矛盾**（刚说信他，下一拍投他），
> 观众立刻出戏。宁可弃权，也不要随机。

## 5. 评分 / 评测：能复用什么、必须新写什么

**能复用（扑克已有）**：

- LLM 调用的全链路（多厂商、流式、超时重试、token 预算、降级）——**原样复用**；
- `cleanThinking` / JSON 容错解析 / 漏牌检测 → 改名成 `leakFilter` 即可跨游戏复用；
- 读人笔记的「每 N 轮更新 + 中文校验 + 白名单」；
- persona 系统（8 种性格 → 两个游戏都能用，但**字段要扩**：加「发言长短习惯 / 推理方式 /
  常见误判 / 拿狼伪装风格 / 压力反应」，见 wolfcha 的 persona 字段表）；
- 回顾面板（结算后回放所有人的 `thinking`）；
- 座位/立绘/节奏控制。

**必须新写**：

| 项 | 为什么新写 |
| --- | --- |
| 阶段状态机 | 扑克只有「下注轮」，狼人杀有夜/天/投票/技能中断，卧底有描述/投票轮 |
| 投票计票 + 平票规则 | 扑克没有「多人投票」 |
| 权限矩阵（谁能看什么、谁能在什么阶段行动） | 扑克只有「自己的底牌」一条规则 |
| 记忆压缩（日摘要） | 扑克靠「读人笔记」跨手，不需要日内摘要 |
| 引用校验 | 新能力 |
| 评测指标与日志格式 | 见下 |

**评测指标（建议第一版就埋点，否则后面无法比较模型）**：

狼人杀：

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 阵营胜率 | 好人胜率 / 狼人胜率（按模型分别统计） | 最基础；注意自对弈要平衡（Werewolf Arena 用「同一模型两阵营各 5 局」） |
| 预言家报验准确率 | 报出的查验中真狼比例 | 衡量「查杀质量」 |
| 好人误投率 | 好人投出的票里投到好人的比例 | 衡量「推理质量」 |
| 狼人存活轮数 | 狼平均活到第几天 | 衡量「伪装质量」 |
| **发言-投票一致率** | 发言里表态的投票目标 == 实际投票目标 | 直接对应「投票不一致」这个坑 |
| **幻觉率** | 引用了不存在的发言/事件的条数 ÷ 总发言数 | 对应「编造前情」 |
| **越界率** | 说出私有信息的条数（过滤器命中数） | 对应「自曝」 |
| 套话率 | 与历史发言 n-gram 重合度 > 阈值的比例 | 对应「全员复读」 |
| 平均发言长度 / 长度方差 | 字数 | 用来调「啰嗦=可疑」 |

谁是卧底：

| 指标 | 定义 |
| --- | --- |
| 卧底存活轮数 | 卧底平均活到第几轮 |
| 平民首投命中率 | 第 1 轮投票投中卧底的比例（衡量描述的信息量） |
| 卧底抄袭率 | 卧底描述与历史描述的 n-gram 重合度 |
| 自曝率 | 说出自己的词的次数 / 局 |
| 自省准确率 | `self_read` 与实际阵营一致的比例（**这个指标最有趣**：模型能不能意识到自己在骗人） |
| 局时长 / 调用数 / token 成本 | 工程指标 |

**统一的日志格式**（一局一个 JSON，事后可回归）：

```json
{"game":"werewolf","config":{"players":7,"roles":{"werewolf":2,"seer":1,"witch":1,"villager":3}},
 "models":{"1":"deepseek-chat","2":"gpt-4o-mini"},
 "events":[{"seq":1,"phase":"night","actor":3,"type":"kill","target":5,"visibility":"faction"}],
 "result":{"winner":"villagers","days":3},
 "metrics":{"hallucination_rate":0.03,"vote_speech_consistency":0.86,"leak_rate":0.0}}
```

## 6. 成本与延迟（实测估算的锚点）

| 游戏 | 人数 | 一局调用数 | 单次延迟 | 一局时长（串行） | 优化后 |
| --- | --- | --- | --- | --- | --- |
| 扑克（现状，参考） | 2~9 | 每手 2~9 次决策 | 1~5s | 一手 20~60s | — |
| **谁是卧底** | 6 | ~48 | 0.5~2s | 1~2 分钟 | 投票并行 → 更快 |
| **狼人杀** | 7 | ~60~65 | 1~4s | 3~6 分钟 | 夜间并行 + 投票并行 + 摘要异步 → 2~3 分钟 |

结论：**先做谁是卧底**（便宜、快、规则简单、验证「多轮记忆 + 结构化输出」这套机制），
再做狼人杀（复用同一套 Kernel/View/Memory，只加阶段与角色）。
