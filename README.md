# 德州荷官 · Poker Dealer

你当**荷官**,而且是**坐在桌边的真 3D 第一视角**——画面是用 three.js 实时渲染的牌房:你在桌子这一侧,面前是自己手里的牌,桌子对面和两侧坐着一圈卡通牌手,公共牌和筹码摊在绿色毡布上。

**你只负责发牌、控节奏、看牌,不参与下注,也没有自己的手牌。** 桌上 2~9 个座位全是 AI,每个都是**独立的大模型代理**:只看得到自己的底牌和公共牌,不知道别人手里是什么,也不共享任何上下文。

它们各有性格(大多是正常牌手略微偏某一门,只有个别偏极端),每一步行动会用一两句中文说出自己在想什么。**默认是手动模式**:气泡会一直留着,直到你点「下一位」,看得清清楚楚;也可以切成自动,让它们自己打(自动时气泡至少完整停留 5 秒)。

**每个角色可以分别指定不同的 LLM**(DeepSeek / Groq / OpenRouter / Gemini / 硅基流动 / 本地 Ollama…)。

## 快速开始

有两种用法:**桌面版**(Electron)和**浏览器版**(部署到 Cloudflare,手机可玩)。
牌局逻辑、3D 场景、AI 代理都是同一套代码。

### 桌面版(Electron)

```powershell
cd Z:\Workspace\poker-dealer
npm install          # 已经装过就跳过
npm start            # 启动桌面应用
```

也可以直接双击 `启动游戏.cmd`(会自动检查依赖,并清掉可能干扰 Electron 的 `ELECTRON_RUN_AS_NODE`)。

### 浏览器版(手机可玩)

```bash
npm run web:build && npm run worker:build
npm run worker:deploy        # 部署到 Cloudflare
```

前端与转发层合成一个 Worker,同源、零配置。**完整的部署与配置说明见
[`docs/DEPLOY-WEB.md`](docs/DEPLOY-WEB.md)**。

> 📄 **文档用英文文件名**(`DEPLOY-WEB.md` / `FRONTEND-GUIDE.md` / `GAME-LOGIC-AUDIT.md`)。
> 中文文件名的同名副本也在 `docs/` 里、内容完全一样,但**有些编辑器打开中文名路径会报

本地想先看看效果:`npm run web:serve` 然后浏览器打开 `http://127.0.0.1:5173`。

首次打开是**主页**,先选模式:

| 模式 | 说明 |
|---|---|
| **荷官模式** | 你就是荷官:发牌、控节奏、看别人打。你能看到所有人的底牌(默认盖着,可切换三态),也能看到每个人的思考。 |
| **玩家模式** | 你自己上桌打(坐 0 号位):有底牌、自己下注。**牌局进行中看不到别家的牌,也看不到他们的思考**;AI 思考完之后气泡会原地显示「他做了什么」(例如「跟注 20」),看完自然消失。等这一手结束,点手牌一览里的「📋 第 N 手记录」再回头看所有人当时在想什么。 |

主页右下角还有 **「跳过,直接用上次设置开局」**,省掉设置这一步。

进入任一模式后都是**开局设置面板**:人数、牌堆、筹码、盲注、**升盲模式**、**大盲前注**、AI 用哪家模型、**节奏模式**。

### 手牌一览

画面底部这一条同时是「牌面放大镜」+「计分板」:

- **公共牌**单独一行,用清晰的正面牌画出来 —— 桌面上的公共牌是 3D 小模型,坐着斜看容易看不清牌面;
- 每个人的名字、筹码、位置(大小盲/按钮位)、底牌与动作;
- **宽度跟着侧栏走**:侧栏打开时给它让位,侧栏收起时铺满底部。
  让出的宽度统一走 CSS 变量 `--strip-right-panel`,窄屏的媒体查询里只改这个变量 ——
  否则媒体查询里的 `right` 会盖掉「铺满」的规则(这个坑我踩过一次)。

### 玩家模式的操作

顶栏会收掉荷官专属的入口(底牌三态 / 气泡开关 / 思考记录),侧栏也只留「荷官记录」。
「⚙ 设置」打开抽屉后,里面多了 **「↩ 退出本局,回主页」**。

#### 常驻信息条(随时知道自己的状况)

操作条上方有一条**一直显示**的信息条 —— 不看手牌一览也能知道现在什么情况:

| 显示项 | 说明 |
|---|---|
| **我的筹码** | 最显眼的一项。数字变化时**滚动过渡**(递增/递减有颜色),结算时闪一下 |
| 位置 | BTN / SB / BB / UTG / CO … |
| 底池 | 当前总底池 |
| 本轮已投 | 只有真投了才显示 |
| 本手结果 | 手牌结束后弹出:赢是绿色 `+1200`,输是红色 `-200`,打平灰色 |

上面还有一行**提示行**,直接说清现在的状态:

- 轮到你 → `轮到你:跟注要 63,也可以弃牌或加注`(金色 + 呼吸光晕)
- 别人行动 → `等待 小林 行动…`
- 手牌结束 → `本手结束:你赢了 1200`

> 这条信息条是后加的。之前筹码/位置/结果只在别处一闪而过,玩家没法随时知道自己
> 还剩多少筹码、上一手是赚是亏 —— 所以做成了常驻,并且把「该你做什么」直接写成一句话。

#### 三个按钮

轮到你会浮出**三个按钮**(底边正好贴在手牌一览上方;轮到你时**不会**把一览收起来):

| 按钮 | 快捷键 | 说明 |
|---|---|---|
| 弃牌 | `F` | |
| 过牌 / 跟注 N | `C` | 需跟多少直接写在按钮上,不另占一行 |
| 加注 / 下注 | `R` | 点它才展开金额浮层 |
| 确认 | `Enter` | |

加注浮层挂在**按钮行内部**、用 `bottom: calc(100% + 8px)` 定位,所以永远在按钮上方 ——
偏移量不依赖按钮高度,以后改按钮尺寸也不会挡到它。

快捷尺度**按局面给**(空间不够时自动去掉放不下的):

- **翻前** → 按大盲倍数:`2BB / 2.5BB / 3BB / 4BB`
- **翻后** → 按底池比例:`1/3池 / 半池 / 3/4池 / 满池`
- 两种情况都带 `最小` 和 `全下`

也可以用滑杆或直接输入数字。低于最小加注的金额会被拒绝(不会静默变成跟注)。

> **定位这块踩了三个坑,都记一下:**
> 1. 按 `offsetHeight` 反推位置 —— 内容一变高度就变,那一帧读到旧值,浮层直接压住手牌一览;
> 2. 用 flex 排列子元素 —— 零高度容器里子元素从顶边往下排,方向不受控,
>    `translateX(-50%)` 还会按零宽度算歪(实测 X 偏了 280px);
> 3. 用常量算浮层偏移量 —— 常量写 61,实际渲染出来不是。
>
> 最后的做法:**容器零高度 + 各块绝对定位贴底边 + 浮层用 `bottom:100%` 挂在自己父元素上**。
> 结构上保证,不靠算。

### 界面文案:只留必要信息,并且随模式变

界面上不再有解释性文字。空位本身就说明了还差几张牌,按钮上就写着该点什么,
所以这些统统删掉了:手牌一览旁的「只能看到自己的牌…」、公共牌行的「还差 N 张」、
底部的「点『发牌 / 下一手』开始第一手」、设置里的「本地模型不需要 Key,完全免费离线」等等。

保留的只有**真的需要提示**的一种情况:手动模式下等你看完某个 AI 的思考
(「看完 XX 的想法了?点『下一位』继续」)—— 因为那时候界面是静止的,不说一句会以为卡住了。

**称呼也随模式切换**,不再出现跟当前模式冲突的说法:

| 位置 | 荷官模式 | 玩家模式 |
|---|---|---|
| 顶栏 / 侧栏页签 | 荷官记录 | **牌局记录** |
| 设置面板说明 | 「你是荷官:坐在桌边发牌…」 | 「你自己上桌打…」 |
| 设置面板开始按钮 | 开始 | 开始牌局 |

> 写了个 `tools/textaudit.mjs` 把源码里所有中文文案抽出来分类(`说明性` / `提到荷官`),
> 改完再跑一遍确认两类都是 0 条。以后加文案可以拿它过一遍。

### 玩家模式的节奏:AI 之间不会再等按钮

玩家模式**强制走自动节奏**(`flow.mode = 'auto'`,气泡停留 0)。

这不是偷懒,是必须的:手动模式下 `waitAfterThink()` 会 `await` 一个只能由「👉 下一位」解开的 Promise,
而那个按钮在玩家模式里是**隐藏的** —— 一旦停在手动模式,AI 每走完一步就永久挂住。

> 这个 bug 用**本地策略**时立刻暴露(决策瞬间返回,卡死看得清清楚楚),
> 接真模型时只是"慢",反而不容易发现。
>
> ⚠️ 这里记一次**修错了方向**的教训:`FlowController` 当时加了
> `manualTimeoutMs`(默认 60 秒)兜底 —— 手动模式等「下一位」超过一分钟就自动放行。
> 结果荷官模式下你正看着牌面想事情,**一分钟后它自己就往下走了**,
> 看起来就是「明明选了手动却还是自动下一位」。
>
> 拿「一分钟后自动继续」去兜「按钮可能被藏起来」,代价是把手动模式的核心语义
> 破坏掉了。现在 `manualTimeoutMs` **默认 0 = 不超时**,真正的修法是
> 「按钮该在就在,不在了去修按钮」,而不是让手动模式自己变自动。
> (`tools/manualcheck.mjs` 守着这个行为。)


### 信息隔离是怎么做到「真看不到」的

不是靠界面藏起来,而是**数据根本不下发**:

```js
// engine.viewForDealer() —— 玩家模式下
players: st.players.map((p) => (human === null || p.seat === human
  ? { ...this.publicPlayer(p), hole: p.hole.slice() }   // 我自己:给底牌
  : { ...this.publicPlayer(p), hole: [null, null] })),  // 别人:只有张数
```

所以就算打开开发者工具翻 `window.__poker.engine`,也拿不到别家的手牌。

**回顾走的是另一个方法 `reviewHand()`**,它有两道闸:
1. 只有玩家模式能调(`humanSeat !== null`);
2. 这一手**没结束就抛错** —— `throw new Error('这一手还没结束,不能查看别家手牌')`。

于是「结束前看不到、结束后能看到」是由引擎保证的,而不是 UI 的自觉。

> 一个容易忽略的细节:筹码在这一手打光的玩家,结算时**不能立刻清掉底牌** ——
> 否则回顾里就看不到他到底拿的是什么了。清底牌的动作挪到了下一手开始的 `startHand()`。
想给每个 AI 单独配模型,进牌桌后点顶栏 **🤖 模型**。

> **不填任何 Key 也能玩**:AI 会退回内置的本地策略(牌型评估 + 底池赔率 + 性格权重),
> 牌局一样能完整打完,只是思考文本是规则生成的。
> 想先看看效果,直接点「用本地策略试玩(不需要 Key)」。

Key 只保存在你这台机器上(`%APPDATA%\poker-dealer-sim\settings.json`,明文)。

## 节奏控制(看清他们在想什么)

这是这个模拟器的重点:AI 的思考过程要看得清,而不是一闪而过。

| 模式 | 行为 |
| --- | --- |
| **👆 手动**(默认) | 每个 AI 想完之后,**思考气泡会一直留在屏幕上**,直到你点「下一位」(或按 `空格`)。想反复读、想截图都行。 |
| **👆🔁 手动 + 连打** | 同上,但一手结束后自动发下一手。 |
| **▶️ 自动** | 完全不打断;每个气泡**至少完整停留 5 秒**再继续。 |

- 底部的「👉 下一位」按钮在等待你的时候会**呼吸发光**。
- **⏱ 速度**按钮:0.5x / 1x / 1.5x / 2x / 3x,调快或放慢整体节奏。
- **🧠 思考记录**(或按 `T`):右侧栏第二个标签,把**每一次决策的完整思考**都记下来 ——
  谁、什么时候、什么牌面、想了什么、最后做了什么、用的是哪个模型。错过一条也能回看。

## 你作为荷官能做什么

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 发牌 / 下一手 | 底部按钮(或按 `空格`) | 开始一手牌;一手结束后再点继续 |
| **推进思考** | 底部 `👉 下一位`(或按 `空格` / `回车`) | 手动模式下放行当前这一位,让下一位开始思考 |
| 节奏模式 | 底部 `👆 手动` | 手动 → 手动+连打 → 自动 循环(或按 `A`) |
| 节奏速度 | 底部 `⏱ 1.0x` | 0.5 / 1 / 1.5 / 2 / 3 倍速 |
| **底牌可见度**(三态) | 顶栏 `🂠 底牌`(或按 `P`) | `盖着` → `只看公共牌` → `全部翻开`。翻开是**荷官特权**:只有你看得到,AI 无感知 |
| 思考气泡开关 | 顶栏 `💭 气泡` | 关掉就只看到动作,保持神秘感 |

> **思考气泡现在会先显示「正在思考中…」**(带动画点),模型开始吐字后立刻接上内容。
> 这样「在等他」和「卡住了」能一眼分清。
>
> **关于 DeepSeek 的思维链**:deepseek 的思考模式**保持开启**(那是它的强项),
> 只用 `reasoning_effort: 'low'` 控制推理长度(`src/shared/providers.mjs` 的 `requestExtra`)。
> `reasoning_content` 是英文的、还夹着给模型自己的格式指令(「We need answer JSON only.」),
> 但这个问题在**显示层**解决 —— `tidyThinking()` 会挡掉英文原文(中文占比 < 30% 不显示),
> 只展示正式 JSON 里那个**中文 `thinking` 字段**。
> 提示词里也专门要求了 `thinking` 必须是 40 字以内的中文。
>
> ⚠️ 这里记录一次走过的弯路:曾经因为英文推理刷到气泡上,就用
> `{ thinking: { type: 'disabled' } }` 把思考整个关掉 —— 那是**拿手段当目的**,
> 决策质量不该为了显示好看而让路。正确做法是修显示层,不是砍掉思考。
>
> 万一模型还是吐了英文 thinking,会换成一句按动作生成的中性中文,不会把英文糊到气泡上。
>
> **玩家模式下也会显示这个气泡**(只显示「正在思考中」,不显示思考内容)——
> 否则桌上的人全都不动,你不知道是在等他还是在发呆。
>
> **思考结束之后,气泡会原地接着显示「他做了什么」**(例如「跟注 20」),
> 停留一小会儿再消失。玩家模式下看不到别人的思考,如果气泡直接消失,
> 就只剩「刚才有人动了但不知道动了什么」,还得去翻日志。这个动作气泡
> 只在玩家模式下出现(荷官本来就能看到思考内容),而且是时效性的。
| **思考记录** | 顶栏 `🧠 思考记录`(或按 `T`) | 每一次决策的完整思考文本 + 动作 + 用的模型 |
| 荷官记录 | 顶栏 `📜 荷官记录` | 谁加注到多少、谁全下、边池怎么分 |
| **手牌一览** | 画面下方 | 3D 里的小牌看不清牌面,这里把每个人的底牌用清晰的正面牌列出来(跟随时态:盖着 / 摊牌亮牌 / 全部翻开);可以点「收起」 |
| 模型分配 | 顶栏 `🤖 模型`(或按 `M`) | 给每个座位单独选厂商与模型 |
| 改规则 | 顶栏 `⚙ 规则` | 中途改人数/牌堆/盲注,确认后重开 |
| 摊牌 | 自动 | 摊牌时亮出参与者的底牌,显示牌型名与各家盈亏 |

画面里还有:一圈坐在琥珀色椅子上的对手、他们面前盖着的底牌、桌上的下注筹码与底池、公共牌与牌堆、以及画面下方荷官的袖子。
**轮到谁行动,谁头顶的三角指示器就会变成金色并上下浮动**;大小盲与按钮位在指示器上挂牌标注。

> 座位半径会**跟着人数放大**(2 人 0.88R → 9 人 1.44R),画面窄的时候还会往中间收一点,所以人多时也不会挤成一团、最外侧的人也不会被裁出画面。

### 为什么请求从主进程发

渲染进程直接把请求发给各家 API 会被 CORS 挡掉,而且 Key 会暴露在页面上下文里。
所以这里做了一个 **Electron 主进程代理**(`src/main/config.cjs` 的 `llm:chat`):

- 主进程用 Node 的 `fetch` 发请求,**不受 CORS 约束**;
- **Key 不进页面**,只在主进程与配置文件里;
- SSE 流式解析也放在主进程,**三种格式统一成同一种增量**(`llm:chunk` 回推给界面),界面只管逐字显示「思考」;
- 支持中途取消(`llm:abort`),改规则重开牌局时能立刻掐断请求。

### 按角色分配

`🧠 模型` 面板三层结构:

1. **厂商密钥**:每家填一次,所有座位共用;
2. **默认模型**:没单独指定的座位用它;
3. **逐座位覆盖**:`(跟随默认)` 或指定某家 + 某个模型;也可以给某个座位选「本地策略(不调用模型)」。

典型玩法:让「爱施压」的那位用 Groq 的小模型(快),让「算赔率」的那位用聪明一点的模型(准),
再留一两个座位跑本地 Ollama 做兜底。**任何一个座位调用失败都会自动退回本地策略,牌局不会卡死。**

## 关于「免费白嫖」

这块专门调研过,结论分成「能用的」和「别碰的」。

### ✅ 合法且稳定的免费方案

| 方案 | 免费额度 | 说明 |
| --- | --- | --- |
| **本地 Ollama / LM Studio** | **无限** | 唯一能保证「一局几十次调用」永不被限流的方案;离线、$0。中文 + JSON 输出推荐 Qwen 系 |
| **硅基流动 SiliconFlow** | 有免费模型 | 官方明确「实名认证后使用全部的免费模型」「免费模型调用免费」,Rate Limit 固定 |
| **Groq** | 有免费层 | 速度极快,适合这个应用 |
| **OpenRouter** | `:free` 模型 50 次/天 | 充值 $10 后提到 1,000 次/天,性价比很高 |
| **Cloudflare Workers AI** | 每天 10,000 neurons | 约合每天几十万输出 token,够玩很多局 |
| **阿里百炼(通义)** | 每个模型 100 万 token,90 天 | 一次性新人额度,无需实名即可领 |

**成本参考**:9 个座位 × 一局约 30 次调用 ≈ 270 次,按 DeepSeek 的低峰价算大约 **$0.08/局**;
本地模型则是 **$0**。所以这个应用根本不需要走灰色路线。

### ⛔ 用各家 AI 网页版「免费聊天」当接口 —— 调研后不建议

这是我在需求里被要求专门探索的一点。我查了技术路径和服务条款,结论是**技术和合规上都不成立**,所以**没有实现**:

**技术层面**(有一份 2026-06 的实测工程记录 [ChatGPT-Web2API](https://github.com/Octo-Lex/ChatGPT-Web2API) 可佐证):

- 从脚本直接 POST 网页版内部接口会返回 **403「Unusual activity」**;
- 需要过一道 **sentinel 三重门**:工作量证明(已被解出)、**Cloudflare Turnstile 人机校验**(必须在浏览器里用官方 widget 解)、以及一个 `so` 挑战(原文标注「likely Kasada-based,尚未解出」);
- 记录里给出的唯一出路是「**驱动页面自身 UI**(模拟输入 + 完整鼠标事件)」——也就是说只能持续对抗 DOM 变动与人机校验;
- **对扑克模拟器是致命错配**:9 个牌手需要并发调用,而单个网页会话只能串行。

**条款层面**(逐字核实过):

- **Anthropic** 消费者条款 §3(7):禁止「access the Services through **automated or non-human means**, whether through a bot, script, or otherwise」——但同时**明确豁免「通过 API Key 访问」**;
- **OpenAI** 使用条款:禁止「**Automatically or programmatically extract data or Output**」,另有账号凭据分享禁令;
- **Kimi** 用户协议 §4:禁止「通过编写或使用**任何自动化脚本、程序、工具**…来**模拟人工操作**」;
- **Google**:措辞相对宽松,以「是否违反 robots.txt」为条件(灰色地带)。

一句话:官方免费渠道是存在的、而且明确欢迎你接 API,走网页自动化等于用「违规 + 随时失效 + 无法并发」去换一个本来就能合法免费拿到的东西。

## 规则实现情况

**完整无限注德州扑克**,不是简化版:

- **边池**:多人以不同筹码量全下时,自动切主池 + 多个边池,只有够资格的人能赢对应池。
- **单挑规则**:两人时按钮位下小盲、翻前先行动、翻后后行动。
- **最小加注**:任何加注的增量,**至少要等于本下注轮中上一次下注或加注的额度**。
  - 翻前视大盲为「上一次下注」→ 最小加注到 2×大盲;
  - 翻后第一个人的「下注」金额不限(只受筹码限制),他下注的额度成为后面的最低增量;
  - 每次完整加注后,基准更新为「本次加注的增量」,所以门槛会跟着涨。
  - **低于最小加注的显式加注会被拒绝并报错**,不会静默改成跟注 ——
    静默降级会把「想加注」悄悄变成「只跟注」,意图被吞掉。
- **短码全下**:增量不足的加注**只可能是全下**,它按**跟注**处理:
  不重开下注轮(已行动的人不恢复加注权)、不改变「上一次完整加注额」;
  但它确实抬高了当前注额,所以**本轮必须继续**,还没行动或被重新拉进队列的人都要补齐。
- **未被跟注的下注退还**:加注后所有人弃牌,多押出去的部分退回本人。
- **平局分池**:平分,奇数余数从**按钮左侧第一家**开始顺时针发。
  (距离要从 `button+1` 起算 —— 用 `seat - button` 的话按钮位自己算出 0,
   会永远把余数拿走,那就不是「按钮左侧最近」了。)
- **短牌(36 张)**:A-6-7-8-9 是最小顺子;牌力顺序改为 **三条 > 顺子**、**同花 > 葫芦**。
  - 实现上,内部判定顺序始终按**真实牌力**(顺子在三条之前),
    短牌只是把**对外类别号**重排(`SHORT_REMAP`),`compare` 用重排后的号比较。
  - 从 7 张里评估 = **遍历所有 5 张子集,取对外牌力最强的那个**。
    不能「把 7 张当一手牌直接判」—— 那会得到一副三条+顺子的混合怪牌,
    和 `best5` 的结果对不上(曾经就是这个 bug,短牌下会在三条/顺子之间判错)。
- **升盲模式(可选)**:每过 **10 个完整人回合**(按钮位转满 10 圈)盲注上升一档,共 21 档:
  `100/200 → 200/400 → 300/600 → 400/800 → 500/1000 → 600/1200 → 800/1600 → 1000/2000 → 1500/3000 → 2000/4000 → 3000/6000 → 4000/8000 → 5000/10000 → 6000/12000 → 8000/16000 → 10000/20000 → 15000/30000 → 20000/40000 → 25000/50000 → 30000/60000 → 50000/100000`。
  起始盲注如果不是表里的档位(比如 10/20),**按倍数放大而不是直接跳到表里某一档** ——
  否则 10/20 会一瞬间变成 300/600。倍率作用在**大盲**上(大盲 ≥ 2,乘 1.5 不会被取整吞掉)。
- **大盲前注(可选)**:大盲位在盲注之外**额外拿出「一个当前大盲」**放进底池。
  这是**死钱**,不计入本轮下注,所以不会抬高注额、也不影响最小加注。
  (和「每人每手前注」二选一,打开大盲前注时普通前注自动归零。)
- **烧牌**:翻牌/转牌/河牌前各烧一张,界面上有烧牌堆。

发牌用 `crypto.getRandomValues` 做 Fisher-Yates 洗牌,纯随机、不设种子。

## 每个 AI 都是独立的

1. **一个座位一个代理对象**(`PokerAgent` 实例),各自持有性格、历史、调用钩子,互相没有引用。
2. **提示词只喂它该看到的**:`viewForSeat(seat)` 里只有它自己的底牌、公共牌、底池、各家筹码与动作,**没有任何人的底牌字段,也没有牌堆信息**。这条有专门的测试守着。
3. **荷官视角是另一条路**:界面用 `viewForDealer()`(含全部底牌),但只有「底牌 → 全部翻开」时才渲染;这个开关不碰任何 AI 的输入。
4. **输出受约束**:模型必须返回 JSON(`thinking` + `action` + `amount`),动作会被引擎按合法动作表规范化;模型抽风给了非法动作,引擎会降级成合法的,牌局永远不会卡死。
5. **失败兜底**:超时/断网/返回看不懂 → 立刻用本地策略接管,并提示是哪一家的调用失败了。

### AI 的记性:它们会记住你怎么打

**默认开启**,可以在设置里关掉或调节频率。

不做这件事的话,AI **每一手都从零开始**:不知道谁刚才连加了三把,不知道谁一直在弃牌,
也不知道你是什么风格 —— 打法就不会有变化,更谈不上针对性。现在改成:

- **跨手公开摘要**(引擎 `state.handDeltas`,只保留最近 5 手)
  每手结束记一条:谁主动下注/加注到多少、谁弃牌、摊牌亮过什么、谁赢多少。
  ⚠️ **弃牌时没亮过的底牌永远不进这个结构** —— AI 的记性只能建立在「真人也能看到」的
  信息上,否则就是在作弊。有专门的测试守着(`tools/notetest.mjs` 的 [4])。
- **AI 自己写「读人笔记」**(每 3 手一次,可在设置里改频率)
  每手结束后的空档(你在看结算画面时),每个 AI 会拿到「最近 3 手的公开过程 + 它上次写的
  笔记」,更新自己对每个人的判断。笔记是**它私有的**,每个 AI 的读法会分歧(跟真人一样)。
  写法要求:必须中文、每条 ≤40 字、必须基于公开证据、没把握就保留旧判断。
- **决策时带上记忆**:每次行动的用户提示词里会多一段「牌桌记忆」,
  里面是最近几手的明细 + 它自己的笔记。实测 6 人桌一段记忆约 1080 字(≈670 token)。

实测效果(3 人桌真实模型连打 7 手,`tools/memorycheck.mjs`)——
笔记会**从模糊变得越来越具体**:

| 时机 | 笔记内容 |
|---|---|
| 早期 | 「小满 — 倾向不明，先按常规应对。」 |
| 后期 | 「小满 — 小满极松凶，K3o也全下；我该只用强牌跟注。」 |
| 后期 | 「老陈 — 会用99接全下、拿A7o全下加注，敢硬拼大注；我少诈唬他，多用实牌价值下注。」 |

> **成本**:每 3 手多 N 次调用(N = 参与人数)。关掉开关或把频率设成 0 就完全不额外花钱。
> **失败处理**:笔记写不出来(模型飘英文、超时)就**保留旧笔记**,绝不影响牌局;
> 单次失败会重试一次,因为这是每 3 手才写一次的长期记忆,丢了可惜。
>
> ⚠️ 关于**笔记必须是中文**:模型偶尔会把笔记写成英文(思考气泡里的英文会被挡掉,
> 但笔记会直接影响决策)—— 那等于一条**看不见的英文指令**在操纵牌局。
> `parseNotes()` 会拒收非中文笔记,并且只接受真正的对手名做键
> (散文兜底会把「第8手」「对付」这类也当成键收进来,实测污染过整份笔记)。

### 筹码与名次:它们知道自己离出局有多远

这是淘汰赛:**筹码归零就出局,最后剩一个人赢下全场**。所以「活着」永远优先于「赢某一个池」。
每手结束后的提示词里都会给出:

**自己的处境(换算成可操作的形式,不只是原始数字)**
```
· 你的筹码:60 = **3 个大盲**,全场第 4 多(共 4 人还在)
  筹码状况:**短码(<10 个大盲,再被盲注磨两圈就没了)**
  —— **你现在最怕的是被盲注磨死**。别用边缘牌跟注磨蹭:
     要么弃,要么等一手好牌直接全下翻倍。
```

> ⚠️ 为什么不能只给原始数字:实测只写「你的筹码:60」时,模型**不会自己换算**成
> 「3 个大盲,快出局了」——它就把 60 当一个数字看。而筹码深度是扑克里最关键的
> 决策依据之一,所以引擎(`stackSituation()`)统一算好大盲数、排名、短/中/深档位。

**全场的处境(对手的筹码也要看得清)**
```
【全场筹码对比】场上还剩 4 人(淘汰一个你的名次就高一位):
    #1 阿哲: 300 个大盲 — 深码
    #2 小满:  45 个大盲 — 深码
    #3 小林:   6 个大盲 — 短码
  → #4 老陈(你): 3 个大盲 — 短码
  〔威胁〕阿哲、小满 筹码比你厚,他们敢跟你全下 —— 别用边缘牌和他们硬碰。
  〔目标〕小林 筹码很浅、最怕被淘汰 —— 对他施压收益最大。
```
档位线用扑克惯例:**< 10 个大盲算短码、> 25 算深码**(正好 10/25 算中码)。
已出局的人会明确标注「已出局(不再参与)」,不会写成「可能在等你先动」。

**名次目标(写进系统提示词)**
```
【筹码就是命】
· 筹码归零你就出局了,这一局对你彻底结束。所以「活着」永远优先于「赢这一个池」。
· 你的名次目标很清楚:尽量拿高名次、尽量避免被淘汰、尽量把别人淘汰掉。
  场上每少一个人,你的名次就高一位 —— 淘汰别人既是收益,也是在给自己腾位置。
· 但也不能一味龟缩:盲注每隔几圈就涨一档,一直不进池会被盲注活活磨死。
  该拼的时候要拼,只是要挑值得的那一手去拼。
```

### 对失败的恐惧:每个角色的风险偏好不同

早先 8 个性格在「怕不怕输」上**完全一样**,而且提示词里只有「第二名没有意义」——
那句话单方向鼓励冒险,没有任何风险警告。现在每个角色有一个 `risk`(0~1):

| 角色 | risk | 提示词里怎么写 |
|---|---|---|
| 磐石 | 0.2 | 极度惜命:非常珍惜筹码,没有很大把握绝不全下,宁可错过也不冒险 |
| 老陈 | 0.35 | 偏保守:怕被淘汰,倾向于挑安全的牌打,不确定的时候宁可弃 |
| 小林/阿哲/老周/小满 | 0.45~0.55 | 风险中性:该保守时保守,牌好、局面合适时也敢押注 |
| 大鹏 | 0.7 | 敢冒险:不怕输筹码,愿意为压力和更大收益去赌,但也不会无脑梭哈 |
| 疯子李 | 0.9 | 几乎不怕输:不在乎把筹码全押出去,敢在边缘局面拼命 |

`risk` **同时**影响提示词和本地兜底策略(`fallbackDecide`),这样断网降级时
不会「突然换个人格」。另外本地兜底也看筹码深度:短码不再用边缘牌跟注磨蹭,
而是「要么弃、要么直接全下翻倍」——与提示词里的指导一致。

实测对比(真实模型,同样的 4 个大盲处境 + 同样的 J9s 边缘牌,前面有人加注):

| 角色 | 决定 | 思考 |
|---|---|---|
| 磐石(极度惜命) | **弃牌** | 「我只有 4 个大盲,J9s 边缘牌,跟 60 等于赌命,不划算。宁可错过。」 |
| 疯子李(几乎不怕输) | **全下** | — |

### 提示词里写的是什么

每个 AI 的系统提示包含这些块(见 `src/ai/agent.js` 的 `buildSystemPrompt`):

- **目标 / 筹码就是命**:淘汰赛语义 + 名次目标 + 「别被盲注磨死」的提醒(见上一节)。
- **风险偏好**:这个角色有多怕被淘汰(见上一节)。
- **这是博弈,不只是算术 —— 光看牌力赢不了**:你赢的钱主要来自**让对手做错决定**,
  不是来自手里的牌好。「牌好就下注、牌差就弃牌」对手一看就懂,永远赢不到大钱。
  **诈唬是核心技能**,而且给了**具体判断条件**(不是空泛的「可以诈唬」):
  对手一路过牌示弱 / 干燥牌面没人能中 / 你在最后位前面都过牌 / 转牌河牌发出吓人的牌 /
  对手人数少。反过来也要求:牌很好时偶尔只跟注设陷阱,对手的大注别轻易被吓跑。
- **读人,不是读概率**:他为什么那样下注?尺度是想让你跟还是弃?他筹码多不多?
  前面几手打得紧还是松?(紧的人突然加注通常真有牌,松的人加注说明不了什么。)
- **性格**:这个座位是稳健 / 算赔率 / 均衡 / 好奇 / 话多心细 / 爱施压,或者两个极端角色之一。
  明确写成「这是倾向,不是套路 —— 紧的人偶尔也要偷一把(否则没人怕你),
  激进的人也要懂得收手」。
- **规则约束**:只能看自己的牌、只能做合法动作、必须输出 JSON。

> ⚠️ 这里也记录一次问题:早先的提示词里有一句「牌力不够就弃牌很正常,拿到好牌才下注」——
> 那句话直接把模型推向「按牌力打」的保守路线,加上 6 个性格的描述都写成了
> 「强牌下注、弱牌放弃」,结果 AI **只会分析牌力、根本不会诈唬**(实测反馈过)。
> 现在每个性格都写清**他怎么骗人 / 什么时候会偷池**,并用
> [`tools/blufftest.mjs`](tools/blufftest.mjs) 守着这个行为:
> 该偷池的局面下注率 100%,危险局面 4/4 弃牌 —— 是**有选择的施压**而不是无脑下注。

给模型的局面描述里也会带上**筹码量情报**(谁是短码、谁是深码)和最后一句提醒:
「想一想:他为什么这么下注?他是真有牌还是在吓你?」

**性格池**(每局随机分配):

| | 名字 | 倾向 | 说明 |
| --- | --- | --- | --- |
| 🪑 | 老陈 | 稳健 | 牌选得紧,但他的紧是伪装 —— 发现别人示弱就下注偷池 |
| 🧮 | 小林 | 算赔率 | 算的不只是「值不值得跟」,还有「这注能不能把他打跑」;听牌爱半诈唬 |
| ⚖️ | 阿哲 | 均衡 | 强牌下注,但同样会诈唬,让对手分不出他手里是什么 |
| 🔍 | 小满 | 好奇 | 小注试探虚实,河牌没人愿弃牌时也敢用大注吓人 |
| 💬 | 老周 | 话多心细 | 擅长读尺度,谁的下注额不对劲就加注施压,牌不好也照样开火 |
| 🏋️ | 大鹏 | 爱施压 | 偏进攻,诈唬比例最高,但遇到明显强牌会收手 |
| 🪨 | 磐石 | **极紧** | 只玩真正的好牌,他加注时大家都知道要小心 |
| 💥 | 疯子李 | **极激进** | 桌上的异类,什么牌都想打,不太服输 |

大多数角色是「正常牌手略微偏一门」,只有最后两个是刻意保留的极端性格。
实测入池率的梯度(625 手样本,`tools/playstats.mjs`):磐石 ≈30% → 老陈 42% → 小林/老周 ≈51% →
阿哲 57% → 大鹏 72% → 小满 76% → 疯子李 94%。

> 注:`personas.js` 里的 `vpip` 等参数只用于**本地兜底策略**,而本地兜底是个近似实现,
> 绝对入池率会整体偏高一些;重点是**排序与梯度**。接上真实模型后,打法由提示词里的性格描述驱动。

## 画面是怎么做出来的

整个牌桌是**真 3D**([three.js](https://threejs.org/) r169,1.3MB 单文件已放进 `vendor/`,运行时不联网):

- **视角**:透视相机摆在荷官座位上方一点点,略微俯视 —— 你看到的是整张桌子、坐在对面的所有人、以及画面下方自己的手(参考图那种构图)。
- **场景**:木地板 + 地毯 + 三面墙 + 背景柜子剪影 + 墙上灯带;桌子是深色包边的亮绿毡布(毡布纹理是 Canvas 现画的),吊灯带阴影投射。
- **配色**:场景主色对着参考图取;角色衣服颜色取自
  [nice-color-palettes](https://github.com/Jam3/nice-color-palettes)(Matt DesLauriers 整理的 100 组专业配色,**MIT**)——
  饱和度和明度都配平过,一桌人放一起不会打架。渲染用**线性色调映射**而不是 ACES 电影级映射,否则卡通配色会被压得发灰发脏。
- **角色**:程序化建模的圆头卡通小人,**统一光头**。
  试过好几种球壳发型(帽檐横切一整圈、发箍、贴着头骨的薄壳),在这种「大圆头 + 简化五官」的比例下都做不像 ——
  边缘要么横切到眼睛显得像贼,要么像戴了顶小帽子;既然整体是极简卡通风,光头最干净,也少一堆容易出错的几何体。
  衣服颜色、体型(瘦/普通/壮)、肤色都按座位和性格变化。胳膊就是一条圆润的圆柱,搭在桌沿上。
  **角色不投射也不接收阴影**:躯干是拼接的,自阴影会在胸口留下一道深色接缝。
- **座位绑定**:一个座位 = 一个 rig 组,人物和椅子都是它的子节点、共用同一个位置与朝向,
  「人坐在椅子上」由结构保证,不会出现各算各的坐标导致错位。
- **头顶指示器**:每个还在牌局里的座位头顶有一个**朝下的三角锥** ——
  轮到谁行动谁就变金色并上下浮动,赢家变绿;锥体上挂一块小牌子标位置
  (`D` 按钮位 / `SB` 小盲 / `BB` 大盲,以及 `UTG`/`HJ`/`CO`)。
  弃牌和淘汰的座位会把指示器收起来,桌上不留悬空标签。
- **牌**:牌面用 Canvas 2D 画好当贴图(点数、花色、人头牌都有),背面是蓝色斜纹 + 金边。公共牌平铺在桌上,各家的底牌摆在各自面前。
  原来的尺寸会让公共牌挤成一排、容易压到筹码,缩到 70% 之后间距刚好;
  **公共牌间距和底牌间距都写成「基准值 × (CARD_SCALE / 1.28)」**,改缩放系数时不用再逐处手调。
  牌面贴图的分辨率不跟着缩,所以牌变小反而更清晰。
- **发牌动画**:牌**从牌堆飞出来**,而不是凭空出现在位置上。
  - 起点是牌堆顶面的**世界坐标**,落点是布局算好的位置;
    牌挂在座位组/公共牌组下(局部坐标),所以要把牌堆的世界坐标换算回各自的父节点局部坐标 ——
    不换算的话牌会从场景原点起飞、或者飞到桌子外面去。
  - 飞行走一条**抛物线**(中途抬高 ~0.5,首尾落在目标高度),ease-out 收尾,落地时轻微放大再收回 ——
    看着像「滑过去停住」而不是瞬移。
  - **错峰**:底牌两张隔 110ms;公共牌每张隔 130ms(翻牌圈一次 3 张时特别明显)。
  - 用的是自己写的插值(不是 `AnimationMixer`)—— 这里动的是普通 Mesh,
    用 mixer 要先生成 clip + 轨道绑定,比直接插值还长。
    已结束的动画会从表里剔除,不会每帧遍历越来越长的死列表。
  - `animationTrail()` 记下每次飞牌的真实起止点(含世界坐标),
    测试读它就能**确定性地**验证「确实从牌堆飞出」,不依赖 rAF 采样运气 ——
    采样抓起点很不稳,第一帧经常已经落在动画中段(曲线是 ease-out,起步快)。
- **筹码**:按面值分色、带侧边条纹的圆柱堆,底池和下注各一堆。
  尺寸由 `cards3d.js` 里的 `CHIP_K`(=0.3)统一控制 —— 缩放直接烘进几何体和堆叠间距,
  `table3d.js` 里那些「相对偏移 × scale」的调用不用动。
- **结算动画**:一手结束时,筹码**从底池飞向赢家**。
  - 金额以**引擎的 payouts 为准**(不是缓存的底池显示值 —— 那个是渲染近似,
    实测会比分出去的钱少,拿它飞动画对不上账)。
  - 按面值分成几批飞(每批最多 4 个筹码),大额先走;多个赢家之间再整体错开。
  - 落到赢家**自己的筹码堆**上。⚠️ 落点别用「下注区往座位方向插值」——
    下注区本来就在座位与桌心之间,再往座位插值反而拉回桌心(实测落点距桌心只有 0.15)。
  - 落地时赢家的头顶指示器**弹一下 + 发光**:这个效果叠加在常规状态之上,
    所以先算好基础位置再把闪烁加进去。
  - **主池 / 边池都能正确区分** —— 直接用引擎 `lastResult.pots` 的合格者名单,
    边池只飞给够资格的人(实测一手里出现过 4 个池、4 种不同的合格者组合)。
  - 金额只要**大致**对得上就行(它是纯视觉,真正给多少由引擎结算)。
- **荷官的手**:画面下方伸进来的袖子和手。**荷官不给自己发牌** —— 没有属于你的两张牌。
- **HUD 是 DOM 叠层**:底池标签和思考气泡每帧用 `camera.project()` 贴到 3D 位置上。
  每个人的名字、筹码、位置、底牌都在画面下方的**手牌一览**里 ——
  3D 场景里**不再有头顶名牌**,不会挡住人脸。

> ⚠️ 老实说:这是**程序化生成的卡通 3D**,风格上接近但**达不到**参考图那种手工建模 + 手绘贴图 + 骨骼动画的成品感(那种需要 Blender 导出的 GLB 模型)。现在没有骨骼动画,只有头部/身体的姿态变化和指示器高亮。

    home.js              主页:选荷官 / 玩家模式

  ui3d/
    scene.js             renderer / 相机 / 灯光 / 房间

### 关于穿模

3D 场景最容易出问题的是「物件互相插进去」。这个用一个专门的工具来管:
`tools/clipsweep.mjs` 会把场景里每个网格的**顶点**变换到世界坐标,检查

- 有没有顶点**既落在桌子圆柱范围内、又低于桌面**(=钻进桌子里);
- 摆在桌上的东西有没有**超出毡布/包边**;
- 有没有两个独立物件**互相穿插**(父子嵌套和「人坐在椅子上」这种正常接触会排除)。

调参时踩过的坑:用包围盒判断会大量误报(斜着摆的胶囊、环形的躯干,盒角都落在空处),
所以最终必须**逐顶点**判断;另外「人与自己的椅子」在数学模型上必然相交(半身模型坐在坐垫上),
所以要单独按「坐垫面以上的交叠体积」来判断。

最终结果:2~9 人桌 **「插进桌子」「超出桌面」都是 0**;剩下的只有几处体积 0.001~0.01 的
毫米级接触(牌和筹码并排摆着),视觉上不可见。

### 关于流式思考的「乱码」

模型是流式返回的,刚吐出 `{"thinking":"我` 的时候,如果直接显示就会看到半个 JSON。
`src/ui/app.js` 的 `tidyThinking()` 负责把 thinking 字段抠出来、清掉转义与 JSON 语法,
**在整理不出人话之前一律返回空**(界面显示「正在思考…」而不是乱码),整理完还要过一次
`hasThinking()` 校验(必须含中文、且去符号后不少于 2 个字)才会显示。

> `npm run test:ui` / `test:layout` / `shots` 需要 Electron 以真实模式启动。
> 如果 shell 里设了 `ELECTRON_RUN_AS_NODE=1`(某些 IDE 终端会设),
> 先执行 `$env:ELECTRON_RUN_AS_NODE=$null` 再跑。

## 已知限制

- **3D 是程序化生成的卡通风格**,不是手工建模的成品:角色由基础几何体拼成,**没有骨骼动画**
  (只有头部/身体姿态变化、脚下高亮圈、气泡与飘字)。要做到参考图那种质感,需要引入 Blender 导出的 GLB 模型 + 骨骼动画系统。
- 软件渲染(SwiftShader,无 GPU 的机器)下帧率较低,功能都正常但画面会有点顿;有独显/核显的机器是流畅的。
- AI 之间**不会互相建模**(不根据对手历史调整范围),只看当前这一手的公开信息 + 自己的性格参数。
  想让它更「读人」,可以在 `src/ai/agent.js` 的 `buildUserPrompt` 里加上历史战绩摘要。
- **你是荷官,不是牌手**:2~9 个座位全是 AI,你没有手牌、也没有下注按钮 —— 你负责发牌、控节奏、看牌。
- 每次 AI 决策是一次独立的流式请求(DeepSeek 约 1~5 秒),9 人桌一手牌大约 20~60 秒;
  嫌慢可以把「行动前停顿」调到 0、把节奏切「自动」,或给部分座位换成 Groq / 本地模型。
- 只在 2~9 人、无限注、无 straddle / 无 all-in insurance 的常规规则下测试过。
